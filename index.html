Eksperimen 5 Script Parsing & Defer

5. Analisis Script di Head Tanpa Atribut Defer

Mengamati dan menjelaskan apa yang terjadi jika script JavaScript dieksekusi di <head> sebelum elemen HTML selesai di-parse.

⚠️ Fenomena & Penjelasan Teknis:

Jika tag <script src="script.js"></script> ditaruh di dalam tag <head> tanpa atribut defer atau async:

  • Browser langsung mengunduh dan mengeksekusi script seketika itu juga (parser-blocking).
  • Pada saat itu, elemen <body> dan elemen dengan ID seperti #judul, #tombolAksi belum selesai dibaca (diparsing) oleh browser.
  • Akibatnya, fungsi pemanggilan seperti document.getElementById("judul") akan menghasilkan nilai null.
  • Ketika program mencoba mengakses atribut elemen seperti judul.textContent = ..., browser akan melempar pesan kesalahan runtime: Uncaught TypeError: Cannot set properties of null (setting 'textContent').

💡 Solusi Standar Modern:

1. Gunakan atribut defer pada tag script di bagian head (seperti yang digunakan pada praktikum ini: <script src="script.js" defer></script>). Browser mengunduh file secara asynchronous dan hanya mengeksekusinya setelah seluruh dokumen HTML selesai diparsing.
2. Atau letakkan tag script tepat sebelum penutup </body>.
3. Atau bungkus kode JS dengan event listener document.addEventListener("DOMContentLoaded", () => { ... }).

1. Apa yang dimaksud dengan DOM dan apa manfaatnya?

Document Object Model (DOM) adalah antarmuka pemrograman (API) standar yang merepresentasikan struktur dokumen HTML atau XML sebagai pohon objek (object-oriented tree hierarchy). Setiap tag HTML, teks, dan atribut dalam halaman web direpresentasikan sebagai sebuah node objek yang memiliki properti dan metode bawaan.

Manfaat Utama DOM:

  • Manipulasi Dinamis: Memungkinkan JavaScript mengubah teks, elemen HTML, dan atribut kapan saja tanpa perlu me-reload seluruh halaman.
  • Interaktivitas Tinggi: Memungkinkan developer merespons aksi pengguna (klik, input, hover, scroll) secara langsung melalui event handling.
  • Manipulasi Gaya/CSS: Mengubah style visual, animasi, dan kelas CSS secara fleksibel secara real-time.
2. Apa perbedaan getElementById(), querySelector(), dan querySelectorAll()?
Metode Jenis Selector Hasil Pengembalian Kecepatan & Karakteristik
getElementById(id) Hanya nama ID (tanpa simbol #) 1 elemen tunggal spesifik (atau null) Paling cepat (dioptimasi khusus oleh browser)
querySelector(selector) Selector CSS bebas (#id, .class, tag, atribut) 1 elemen pertama yang cocok Sangat fleksibel untuk seleksi spesifik
querySelectorAll(selector) Selector CSS bebas Koleksi NodeList statis dari semua elemen yang cocok Mendukung perulangan seperti .forEach()
3. Apa fungsi addEventListener() dan sebutkan tiga contoh event?

Fungsi addEventListener() adalah metode resmi pada objek DOM EventTarget untuk mendaftarkan fungsi penanganan (event handler / listener callback) pada suatu elemen HTML yang akan dieksekusi ketika suatu jenis kejadian (event) tertentu terjadi pada elemen tersebut.

Keunggulannya dibanding inline handler (seperti onclick) adalah dapat memasang beberapa listener sekaligus pada event dan elemen yang sama tanpa saling menimpa.

Tiga Contoh Event:

  • click: Terjadi saat pengguna menekan tombol mouse atau menyentuh tombol/elemen di layar (misal tombol kirim atau toggle).
  • input: Terjadi secara langsung setiap kali nilai pada <input> atau <textarea> berubah (sangat ideal untuk live character counter).
  • submit: Terjadi saat pengguna mengirimkan form (misal menekan tombol submit atau tombol Enter dalam form).
4. Mengapa event.preventDefault() digunakan pada event submit form?

Secara bawaan (default behavior), ketika event submit terjadi pada elemen form, browser web akan langsung mengarahkan halaman ke URL tujuan (atribut action) dan melakukan refresh atau navigasi ulang seluruh halaman (page reload).

Tujuan Pemanggilan event.preventDefault():

  • Menghentikan aksi refresh otomatis browser sehingga proses eksekusi tetap berada pada halaman aktif.
  • Memberikan kesempatan bagi JavaScript untuk memeriksa kelengkapan data (validasi client-side) terlebih dahulu sebelum data benar-benar dikirimkan.
  • Mencegah hilangnya status DOM, teks input, atau pesan error yang sedang ditampilkan ke pengguna.
5. Apa perbedaan textContent dan innerHTML dari sisi penggunaan dan keamanan?
Aspek textContent innerHTML
Penggunaan Menetapkan atau mengambil konten sebagai teks mentah (plain text) murni. Semua karakter tag (seperti <b>) akan ditampilkan sebagai teks literal. Menetapkan atau mengambil konten dalam bentuk markup HTML. String yang dimasukkan akan diparsing oleh browser menjadi elemen HTML nyata.
Keamanan (Security) Sangat Aman. Bebas dari serangan Cross-Site Scripting (XSS) karena browser tidak pernah mengeksekusi markup dari string input pengguna. Rentan XSS. Jika teks input dari user langsung dimasukkan ke innerHTML tanpa sanitasi, penyerang bisa menyisipkan tag <img src="x" onerror="alert(1)"> yang berbahaya.
Kinerja Lebih cepat karena tidak memicu HTML parser browser. Lebih lambat karena browser harus mem-parse string HTML menjadi node DOM baru.
6. Bagaimana classList.toggle() membantu mengubah tampilan elemen?

Metode classList.toggle("namaKelas") bekerja seperti sakelar otomatis cerdas:

  • Jika kelas CSS tersebut belum ada pada elemen, maka fungsi akan menambahkannya (seperti classList.add()).
  • Jika kelas CSS tersebut sudah ada pada elemen, maka fungsi akan menghapusnya (seperti classList.remove()).

Manfaat: Menghilangkan kebutuhan untuk menuliskan logika kondisional manual if (element.classList.contains(...)) { remove() } else { add() }. Sangat efisien untuk membuat tombol highlight, tema gelap/terang (dark mode), accordion, dropdown menu, dan status item to-do list ("selesai" / "belum selesai").

Berikut adalah 5 skenario pengujian komprehensif yang telah diuji dan divalidasi pada praktikum ini:

  2. Skenario Format Email Tidak Valid: Pengguna mengisi nama dengan benar ("Margent"), namun mengisi email tanpa simbol '@' atau tanpa domain (misal: "margentouwen"). Sistem regex mendeteksi pola yang salah dan menampilkan pesan "Masukkan email yang valid.".
  3. Skenario Usia di Bawah Batas Minimum: Pengguna mengisi usia 15 tahun (kurang dari syarat 17 tahun). Sistem validasi memunculkan pesan "Usia harus berupa bilangan bulat 17–100.".
  4. Skenario Usia Bukan Bilangan Bulat / Di Luar Rentang: Pengguna memasukkan nilai desimal (25.5) atau lebih dari 100 tahun (120). Sistem menolak dan meminta angka valid.
  5. Skenario Seluruh Input Valid: Pengguna memasukkan Nama: "Margent Ouwen Sitompul", Email: "margent@gmail.com", Usia: 20 tahun. Sistem menampilkan pesan sukses "Validasi berhasil. Form siap diproses." serta mengosongkan form menggunakan form.reset().
