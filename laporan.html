BAB II. DASAR TEORI

2.1 Document Object Model (DOM)

Document Object Model (DOM) adalah antarmuka pemrograman (API) standar W3C yang merepresentasikan dokumen HTML atau XML sebagai hierarki pohon objek (DOM Tree). Ketika browser web memuat halaman HTML, browser akan melakukan proses parsing kode sumber menjadi objek-objek JavaScript yang dapat dibaca, diubah, dihapus, maupun ditambahkan secara dinamis pada saat runtime tanpa me-reload dokumen secara keseluruhan.

2.2 Pemilihan Elemen (Element Selector)

JavaScript menyediakan beberapa metode utama untuk memilih elemen HTML:

  • document.getElementById("id"): Memilih satu elemen spesifik berdasarkan nilai atribut id. Metode ini merupakan selector paling cepat karena indeks ID dioptimalkan secara langsung oleh mesin browser.
  • document.querySelector("selector"): Memilih elemen pertama dalam dokumen yang cocok dengan selector CSS tertentu (misalnya .class, #id, tag[attr]).
  • document.querySelectorAll("selector"): Memilih seluruh elemen yang cocok dengan selector CSS dalam bentuk koleksi NodeList statis yang dapat diiterasi menggunakan perulangan forEach.

2.3 Manipulasi Konten dan Aspek Keamanan

Untuk memperbarui teks pada elemen, standar modern merekomendasikan penggunaan textContent dibandingkan innerHTML saat menampilkan data masukan pengguna. textContent memperlakukan seluruh string sebagai teks murni (literal string) sehingga mencegah celah keamanan Cross-Site Scripting (XSS) di mana penyerang berusaha menyisipkan skrip berbahaya ke dalam DOM.

2.4 Event Handling & addEventListener()

Event adalah kejadian atau aksi yang terjadi pada browser, seperti pengguna menekan tombol mouse (click), mengetik huruf (input), mengganti pilihan dropdown (change), atau mengirim formulir (submit). Melalui addEventListener(), kita dapat menghubungkan suatu elemen dengan fungsi penangan (callback listener) secara modular tanpa menimpa event listener lainnya.

Pada event submit pada formulir, pemanggilan event.preventDefault() sangat penting untuk menghentikan aksi bawaan browser yang biasanya me-refresh halaman (reload), sehingga verifikasi validasi data dapat diselesaikan secara mulus melalui JavaScript.

BAB V. EKSPERIMEN MANDIRI

5.1 Implementasi dan Analisis 5 Poin Eksperimen Mandiri

1. Tambahkan tombol untuk menghapus satu item dari To-do List

Solusi: Pada fungsi pembuat item to-do, ditambahkan elemen tombol <button> berlabel "Hapus" yang memiliki event listener item.remove() (atau daftarTugas.removeChild(item)). Ketika diklik, node <li> terkait langsung dihilangkan dari pohon DOM.

2. Ubah validasi agar nama minimal terdiri dari tiga karakter

Solusi: Kondisi validasi nama diperluas dari nama === "" menjadi:

if (nama === "") { pesanForm.textContent = "Nama wajib diisi."; } else if (nama.length < 3) { pesanForm.textContent = "Nama minimal harus terdiri dari 3 karakter."; }

3. Tambahkan event change pada dropdown sesi workshop dan tampilkan sesi yang dipilih

Solusi: Dropdown <select id="wsSesi"> dipasangi event listener change. Saat pengguna memilih opsi baru, JavaScript membaca nilai wsSesi.value serta atribut data (deskripsi, pemateri, sisa kuota) dan menampilkannya langsung ke kotak informasi sesi.

4. Buat tombol untuk menyembunyikan dan menampilkan paragraf menggunakan class CSS

Solusi: Dibuat class CSS .hidden-element { display: none !important; } dan tombol aksi yang memanggil paragraf.classList.toggle("hidden-element"). Ketika class ditambahkan, paragraf disembunyikan; saat dicopot, paragraf tampil kembali.

5. Pindahkan script tanpa defer ke bagian head. Amati kemungkinan masalah dan jelaskan penyebabnya

Hasil Pengamatan & Penyebab:
Ketika tag <script src="script.js"></script> ditaruh di dalam tag <head> tanpa atribut defer:

  • Browser web melakukan eksekusi skrip secara synchronous saat membaca bagian head, sebelum dokumen HTML bagian body selesai dibaca (diparsing).
  • Fungsi pemilih elemen seperti document.getElementById("judul") akan mengembalikan nilai null karena elemen HTML dengan ID tersebut belum ada di dalam DOM.
  • Ketika skrip mencoba mengeksekusi judul.textContent = ..., browser akan melempar pesan kesalahan runtime: Uncaught TypeError: Cannot set properties of null (setting 'textContent') dan seluruh skrip di bawahnya akan berhenti bekerja.
  • Solusi Standar: Menggunakan atribut defer pada tag script di bagian head, atau menaruh tag script sebelum tag penutup </body>, atau membungkus kode dalam document.addEventListener("DOMContentLoaded", ...).

BAB VI. JAWABAN PERTANYAAN EVALUASI

Pertanyaan 1: Apa yang dimaksud dengan DOM dan apa manfaatnya?

Jawaban:
Document Object Model (DOM) adalah antarmuka pemrograman berstandar W3C yang memodelkan dokumen HTML sebagai pohon struktur berorientasi objek (tree of objects). Setiap tag, atribut, dan teks diwakili sebagai node objek yang memiliki properti dan metode.
Manfaat DOM:

  • Memungkinkan JavaScript memodifikasi struktur, teks, dan elemen HTML secara dinamis tanpa reload halaman.
  • Mendukung interaktivitas tinggi pengguna melalui event handling (klik, ketik, drag, scroll).
  • Memudahkan pembaruan antarmuka secara modular, cepat, dan responsif.
Pertanyaan 2: Apa perbedaan getElementById(), querySelector(), dan querySelectorAll()?

Jawaban:
Perbedaan ketiganya terletak pada jenis selector yang diterima, nilai kembali, dan performanya:

Metode Argumen Selector Nilai Return Karakteristik
getElementById(id) Hanya string nama ID (tanpa tanda #) 1 objek Element tunggal atau null Performa paling cepat karena browser mengindeks ID secara khusus.
querySelector(sel) Selector CSS apa pun (#id, .class, tag, attribute) 1 elemen pertama yang cocok atau null Fleksibel untuk memilih elemen bersarang spesifik.
querySelectorAll(sel) Selector CSS apa pun Koleksi NodeList statis Mengambil semua elemen yang cocok, mendukung method .forEach().
Pertanyaan 3: Apa fungsi addEventListener() dan sebutkan tiga contoh event?

Jawaban:
Fungsi addEventListener() adalah metode standar pada objek DOM EventTarget untuk mendaftarkan fungsi penanganan (event listener/callback) yang akan dipanggil saat suatu event tertentu terjadi pada elemen tersebut. Keunggulannya adalah dapat memasang beberapa penangan berbeda pada elemen yang sama tanpa menimpa fungsi lain.
Tiga Contoh Event:

  • click: Terpicu saat tombol mouse ditekan atau layar sentuh disentuh pada suatu elemen.
  • input: Terpicu secara instan setiap kali isi teks input/textarea berubah (berguna untuk character counter).
  • submit: Terpicu saat formulir dikirimkan oleh pengguna.
Pertanyaan 4: Mengapa event.preventDefault() digunakan pada event submit form?

Jawaban:
Secara bawaan (default behavior), pengiriman formulir HTML akan memicu browser untuk memuat ulang halaman atau berpindah ke URL atribut action. Pemanggilan event.preventDefault() digunakan untuk membatalkan perilaku bawaan tersebut, sehingga proses validasi formulir dan manipulasi DOM dapat diselesaikan sepenuhnya oleh JavaScript di sisi klien tanpa kehilangan status data atau menyebabkan kedipan reload halaman.

Pertanyaan 5: Apa perbedaan textContent dan innerHTML dari sisi penggunaan dan keamanan?

Jawaban:

Aspek textContent innerHTML
Penggunaan Menyisipkan atau membaca string sebagai teks murni tanpa mengurai tag HTML. Menyisipkan string yang akan di-parse oleh browser menjadi elemen HTML nyata.
Keamanan Aman. Tidak dapat disusupi kode berbahaya karena tag diperlakukan sebagai karakter teks literal. Rentan XSS. Jika teks pengguna disisipkan langsung, penyerang dapat menyuntikkan skrip jahat.
Kinerja Lebih cepat karena tidak memicu parser HTML browser. Lebih lambat karena browser harus mem-parsing markup string menjadi node DOM.
Pertanyaan 6: Bagaimana classList.toggle() membantu mengubah tampilan elemen?

Jawaban:
classList.toggle("namaKelas") berfungsi sebagai sakelar (toggle switch): jika kelas tersebut belum ada pada elemen, method akan menambahkannya; jika sudah ada, method akan menghapusnya. Hal ini menghemat kode karena pengembang tidak perlu menulis logika pengecekan kondisi manual if (el.classList.contains(...)). Fitur ini sangat bermanfaat untuk tombol tema (dark mode), accordion, dan penandaan status selesai pada to-do list.

Pertanyaan 7: Sebutkan minimal tiga skenario pengujian validasi form!

Jawaban:
Berikut adalah 5 skenario pengujian yang telah diuji dan divalidasi pada praktikum ini:

  1. Semua Input Kosong: Pengguna langsung menekan submit; sistem memunculkan pesan "Nama wajib diisi.".
  2. Format Email Tidak Valid: Pengguna memasukkan nama valid tetapi email tidak memiliki domain/simbol '@'; sistem memunculkan pesan "Masukkan email yang valid.".
  3. Usia di Bawah 17 Tahun: Pengguna memasukkan usia 15 tahun; sistem menolak dengan pesan "Usia harus berupa bilangan bulat 17–100.".
  4. Usia Bukan Bilangan Bulat: Pengguna memasukkan nilai pecahan (misal 21.5); sistem menolak.
  5. Semua Data Valid: Pengguna mengisi nama lengkap, email valid, dan usia 21 tahun; sistem memunculkan pesan sukses "Validasi berhasil. Form siap diproses." dan mereset form.

Berdasarkan serangkaian latihan, pengembangan mini project, dan eksperimen mandiri yang telah diselesaikan pada Praktikum 6 (Pertemuan 7) Pemrograman Web, dapat disimpulkan bahwa:
